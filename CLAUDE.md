## 1. What this project is

**{mocaredd}**: Monte Carlo Simulations for REDD+ uncertainty analysis. It's an R
package that contains a Shiny app. It's open source (MIT), maintained at
[openforis/mocaredd](https://github.com/openforis/mocaredd) and deployed at
<https://openforis-shiny.shinyapps.io/mocaredd/>.

### The problem it solves

Under REDD+ (Reducing Emissions from Deforestation and forest Degradation), countries
receive result-based payments for **emission reductions (ER)**. ER is the difference
between greenhouse gas emissions in a **reference period (REF, the baseline)** and a
**monitoring period (MON)**. Every estimate is uncertain because it comes from
sample-based activity data (areas of land use change) and from carbon stock models.

High-integrity REDD+ standards (e.g. ART-TREES, FCPF) increasingly require
**Monte Carlo simulations (IPCC Approach 2)** to quantify this uncertainty. Countries
usually run them in large spreadsheets, which are error-prone, slow, hard to reproduce
and hard to verify. {mocaredd} replaces that with:

1. **A standard XLSX template** that the country fills in: settings, time periods,
   activity data (land use transitions with area and SE), and carbon stocks per land
   use with SE and PDF.
2. **An app** that checks the template, computes arithmetic-mean results with
   **IPCC Approach 1** (error propagation), runs the **Monte Carlo simulations**,
   aggregates them to periods and ER, and shows medians, confidence intervals,
   histograms, forest plots and a **sensitivity analysis** (delta method, variance
   shares, activity data tornado).
3. **An Excel export with live formulas** (`fct_make_XL()`) so that verifiers can trace
   every calculation.

Users are national forest monitoring / MRV teams, FAO technical staff and
verification bodies. The app is offered in English, French and Spanish.

### Technology stack

- **R ≥ 4.1** (the code uses the native pipe `|>`), packaged as a standard R package
  (`DESCRIPTION`, `NAMESPACE` generated by roxygen2, `man/`).
- **Shiny + bslib** (Bootstrap 5) UI, with `bsicons`, `shinyjs`, `shinyWidgets`, and
  `shiny.i18n` for translations.
- **Tidyverse**: `dplyr`, `tidyr`, `purrr`, `stringr`, `rlang` (`.data` pronoun),
  `ggplot2`.
- **gt** for tables (results, forest plots), **readxl** to read the template,
  **openxlsx2** to write the Excel export.
- **testthat** (edition 3) for unit tests; **pkgdown** website; GitHub Actions for
  `R-CMD-check` and pkgdown.
- Deployment: `app.R` + `rsconnect::deployApp()` to shinyapps.io.

## 3. Calculation chain

This chain is the core of the app. It runs in `R/mod_tool_server2.R` and is mirrored in
`tests/running-core-functions.R`.

```
XLSX template
  └─ fct_checkinput()        read + 7 checks → list(all_ok, template_version, data = list(setup, time, area, carbon))
       ├─ fct_arithmetic_mean2()   IPCC Approach 1: emissions per period, REF/MON levels, ER, U%, results table + plot   (used by the app)
       ├─ fct_combine_mcs_E()      MCS per land use transition: simulate AD and C elements (fct_make_mcs), C stock formulas, EF, E
       │    ├─ fct_combine_mcs_P(.period_type = "REF" / "MON")   aggregate to reference / monitoring levels
       │    └─ fct_combine_mcs_ER()                              emission reductions per MON period
       │         └─ fct_calc_res()   median, CI, U% from simulations → fct_forestplot(), fct_histogram()
       ├─ fct_sensitivity2()       delta-method sensitivity → fct_tornado()
       └─ fct_make_XL()            Excel export with live formulas (Approach 1 formulas follow fct_arithmetic_mean3())
```

- **Carbon stock formulas** come from `fct_make_formula2()` (value) and
  `fct_make_formula_U()` (Approach 1 uncertainty), e.g. `AGB * (1 + RS) * CF + DW`.
  They are strings evaluated with `eval(parse())` for each simulation.
- **Emission factor** = C stock initial − C stock final (×44/12 for CO2).
  **E** = AD × EF.
- Server state lives in one `reactiveValues` object, `rv`: `rv$checked` (full output of
  `fct_checkinput()`), `rv$inputs` (the 4 tables), `rv$checks` (`all_ok`, `ari_res`),
  `rv$mcs` (simulations and results).

### Template (version 2 is current, version 1 is still supported)

| Sheet (v2 / v1) | Content |
|---|---|
| `setup` / `user_inputs` | One row: `n_iter`, `dg_ext`, `dg_pool`, `ad_annual`, `conf_level`, `digits`, `ran_seed`, `trunc_pdf` (+ `c_unit`, `c_fraction` in v1). |
| `time` / `time_periods` | `period_no`, `year_start`, `year_end`, `period_type` (`REF`, `REF1`…, `MON`, `MON1`…; empty = period not used in REF/MON). |
| `area` / `AD_lu_transitions` | One row per transition: `trans_period`, `lu_initial`, `lu_final`, `trans_area`, `trans_se`, `trans_pdf`, `redd_activity` (`DF`, `DG`, `EN`, `EN_AF`, `EN_RE`). |
| `carbon` / `c_stocks` | One row per land use × element: `c_period` (`ALL` or a period), `c_lu`, `c_element` (`AGB`, `BGB`, `DW`, `LI`, `SOC`, `ALL`, `RS`, `CF`, `DG_ratio`), `c_unit` (`DM`, `C`, `ratio`), `c_value`, `c_se`, `c_pdf`. |

Key rules:
- **v2 IDs are built from labels** with `label2id()` (lower case, spaces → `_`,
  "forest" removed). Area ID = `period*lu_initial*lu_final`. Carbon ID =
  `[period*]lu*element`.
- **Degradation** has two methods:
  - **C stock difference** between the intact and degraded land uses. `dg_ext` may be
    empty.
  - **`DG_ratio` rows**: `dg_ext` (e.g. `"degraded"`) is removed from a degraded land
    use's name to find its intact land use, and `dg_pool` sets which pools the ratio
    applies to.
  - Code that strips `dg_ext` must handle `NA` (stringr fails when the pattern is
    `NA`).
- `CF` (carbon fraction) is one global `carbon` row in v2. It's required when any
  element is in `DM`.
- `ad_annual`: is activity data already annual (TRUE), or a total over the period?

### Input checks (`fct_checkinput()`)

The 7 steps, in order: load; column names; table sizes; data types; category values;
unique IDs; cross-table consistency. The function stops at the first failed step.
Each table check returns `NULL` (pass) or a text locating the first problem, e.g.
`first problem: col: c_lu, row: 6, value: empty`. Rows are **Excel row numbers**: the
header is row 1. Problems are passed to `failed_tables()` **by name** (`setup =`,
`time =`, `area =`, `carbon =`), never by position. All output goes through
`message()`; the server captures it for the console shown in the app.

## 4. Coding preferences (follow these)

1. **Tidyverse over base R**:
   - `dplyr::filter/mutate/summarise` over `[`, `subset`, `aggregate`
   - `purrr::map*` over `lapply/sapply`
   - `stringr::str_*` over `grepl/sub/paste` where a stringr equivalent exists
   - `tidyr::pivot_*` over `reshape`

   Base R is fine for small scalar logic (`if`, `is.na`, `nrow`, `setdiff`…).
2. **Logical sequencing over functions.** Write code as a readable sequence of numbered,
   commented steps. Only create a helper function when the **same code block is used
   3 times or more**. For 1–2 uses, write the steps inline.
3. Always namespace calls (`dplyr::mutate()`, `stringr::str_detect()`). Never call
   `library()` in `R/`. Exceptions: `shiny` and `bslib` are imported in
   `shiny_run_mocaredd.R`, so they are used without prefix in UI/server code.
4. Use the native pipe `|>` and the `.data$col` pronoun in data-masking verbs (needed
   for `R CMD check`). Use string column names in `dplyr::select()` / `tidyselect`.
5. Prefix function arguments with a dot: `.checked_data`, `.path`, `.period_type`.
6. Section comments follow the existing hierarchy:
   `## 1. TITLE ####`, `## 1.1 Subtitle ====`, `## + detail ----`. Short `##` comments
   explain why, not what.
7. Functions may keep a commented-out `## !!! FOR TESTING ONLY` block of example inputs
   at the top, for interactive debugging. Keep it commented.
8. Every exported function has roxygen docs with `@param`, `@return` and a runnable
   `@examples` using `system.file("extdata/...", package = "mocaredd")`. Run
   `devtools::document()` after changing roxygen or exports. Never edit `NAMESPACE` or
   `man/` by hand.
9. **UI text is never hard-coded.** Add a key to `.tr_keys()` in `R/utils-tr.R` (value =
   English text), add the same English text with `fr` and `sp` translations to
   `inst/assets/translations.json`, and use `i18n$t(.tr$key)` in UI/server code.
10. Keep v1 and v2 template support when changing anything that reads the input tables
    (`check_version` / `is_v2` branches).

## 5. Development workflow

```r
devtools::load_all()          # load the package
devtools::document()          # roxygen → NAMESPACE + man/
devtools::test()              # unit tests (tests/testthat)
devtools::check()             # R CMD check (must stay clean: 0 errors, 0 warnings)
mocaredd::shiny_run_mocaredd()  # run the app locally (or source app.R)
```

Non-interactive (e.g. from an AI agent's shell):

```sh
Rscript -e 'pkgload::load_all(".", quiet = TRUE); r <- fct_checkinput(.path = "inst/extdata/mocaredd-templatev2-simple.xlsx", .minislow = NULL)'
```

- After any change to calculations, run the chain on the 4 workbooks in
  `inst/extdata/` (they must all pass `fct_checkinput()`, and `fct_combine_mcs_E()`
  must run). Also run it on any relevant workbook in `tests/workbooks/`.
- For check changes, also try the broken templates in `data-raw/test-*.xlsx`.
- Monte Carlo means should agree with the Approach 1 arithmetic means
  (`fct_arithmetic_mean2()`) within simulation noise. A large gap means a bug.
- New top-level files must be added to `.Rbuildignore` to keep `R CMD check` clean.
- Write temporary files to the session's temp folder, never to the user's home folder.
- Commit only when the user asks.

## 6. Known state and pitfalls

- The app uses `fct_arithmetic_mean2()`. `fct_arithmetic_mean3()` is the reference for
  the Excel export formulas and the tests. Keep both consistent (e.g. the results table
  has 3 groups: "Emissions by time period", "Reference and monitoring emissions",
  "Emission reductions and removals").
- `fct_make_XL()` is tested through `tests/running-core-functions.R` and isn't yet
  wired into the app's download buttons.
- FAO branding is **on hold** pending authorisation: the logos in
  `shiny_run_mocaredd.R` are commented out and replaced by placeholders. Don't
  re-enable them without being asked.
- Workbooks in `tests/workbooks/` and some in `data-raw/` hold **real country data**.
  Read them only for the task at hand. Never copy their content into code, tests,
  commits, issues or external services.
- `fct_make_mcs()` supports `normal` (optionally truncated at 0 with `trunc_pdf`) and
  `beta`. Other PDFs aren't implemented yet.
